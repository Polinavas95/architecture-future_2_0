1. Технологический радар

[Радар](./Radar.puml)

Привязка к бизнес-сценариям

| Технология             | Бизнес-сценарий                            | Обоснование                                                                          |
|------------------------|--------------------------------------------|--------------------------------------------------------------------------------------|
| Kafka                  | Независимое развитие финтех и ИИ           | Домены общаются асинхронно, без блокировки друг друга                                |
| Iceberg                | Быстрая отчётность                         | Аналитические запросы к Lakehouse в десятки раз быстрее, чем к DWH                   |
| dbt (data build tool)  | Ускорение вывода отчётов                   | Аналитики сами строят витрины, не прося разработчиков писать хранимые процедуры      |
| DataHub                | Самообслуживание                           | Пользователи находят нужные данные без помощи аналитиков; отчёты формируются быстрее |
| OPA                    | Качество медицинских и финансовых сервисов | Разграничение доступа: финтех не видит карты, врачи видят только своих пациентов     |
| FHIR                   | Интеграция с фармой и электроникой         | Партнёры смогут подключиться без переговоров о формате                               |
| Great Expectations     | Качество финансовых отчётов                | Автоматическая проверка: дедубликация кредитов, счета не теряются                    |
| Kubernetes             | Масштабирование для новых бизнесов         | Каждый домен масштабируется независимо при росте нагрузки                            |
|                        |                                            |                                                                                      |

3. Обоснование каждого этапа с точки зрения бизнеса

1) Фундамент

| Бизнес-цель                | Как этап помогает                                                                           |
|----------------------------|---------------------------------------------------------------------------------------------|
| Снижение затрат            | Облачные ресурсы для Lakehouse дешевле поддержки SQL Server                                 |
| Качество сервиса           | Использование Kafka даёт асинхронность (при падении одного домена другие продолжают работу) |
|                            |                                                                                             |

Без Kafka и Lakehouse мы не можем начать выносить логику из DWH. Это фундамент, на котором строится всё остальное

2) Портал самообслуживания

| Бизнес-цель               | Как этап помогает                                                           |
|---------------------------|-----------------------------------------------------------------------------|
| Скорость принятия решений | Аналитики сами строят отчёты, не ждут разработчиков DWH                     |
| Снижение затрат           | Меньше часов работы аналитиков на поиск данных                              |
| Качество сервиса          | Row-level security в портале (финтех-менеджер не увидит медданные случайно) |
|                           |                                                                             |

Бизнес уже жалуется на долгие отчёты. Быстрый MVP портала на первых 10 витринах (по клиникам и финансам) покажет результат и обоснование на дальнейшую разработку

3) Изоляция медицинских данных

| Бизнес-цель               | Как этап помогает                                                                 |
|---------------------------|-----------------------------------------------------------------------------------|
| Скорость принятия решений | Врачи и ИИ-сервисы получают прямой высокопроизводительный API с доступом к картам |
| Качество сервиса          | Медданные больше не смешаны с аналитикой (минимальны регуляторные риски)          |
|                           |                                                                                   |

Изоляция медданных требует переписывания API для врачей и ИИ-сервисов


4) Финтех-независимость

| Бизнес-цель               | Как этап помогает                                                                                |
|---------------------------|--------------------------------------------------------------------------------------------------|
| Скорость вывода продуктов | Финтех может запускать кредитные продукты без согласования с медицинским доменом                 |
| Снижение затрат           | Удаляется дублирующаяся логика: финтех-расчёты не делаются дважды (в DWH и в банковской системе) |
|                           |                                                                                                  |

Логика финтеха сейчас сильно завязана на DWH. Изолируем медицинские данные, чтобы они случайно не попали в финтех-отчёты (регуляторка)

5) Партнёрский домен

| Бизнес-цель                | Как этап помогает                                                                                     |
|----------------------------|-------------------------------------------------------------------------------------------------------|
| Масштабирование            | Подключение фарм-компании и производителя электроники без изменения ядра системы                      | 
| Скорость вывода продуктов  | Новые бизнес-направления (умные рецепты, предсказание поломок оборудования) запускаются в 2-3 месяца  |
|                            |                                                                                                       | 

Ближайшие партнёры появятся не раньше 6-го месяца, поэтому оставляем эту работу на более позний срок


6) Отключение legacy

| Бизнес-цель       | Как этап помогает                                                                            |
|-------------------|----------------------------------------------------------------------------------------------|
| Снижение затрат   | Экономия на лицензиях SQL Server, поддержке ESB и PowerBuilder (ориентировочно $200 000/год) |
| Качество сервиса  | Удаление единых точек отказа и легаси-кода                                                   |
|                   |                                                                                              |
