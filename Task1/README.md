1. Проект архитектуры системы для «Будущего 2.0» через год

[C4 диаграмма](./C4_Container.puml)

1) Портал самообслуживания работает только с витринами из домена «Управление» (агрегированные KPI) без медкарт;
2) Шина Kafka встала на место старой ESB (Enterprise Service Bus), позволяя подключаться через события;
3) Data Lakehouse с открытыми форматами (Delta/Iceberg) как единое физическое хранилище для аналитики с чёткими доменными границами;
4) Легаси DWH временно остаётся только для не перенесённых отчётов, бизнес-логика выгружена в сервисы.

2. Проблемные места в текущей архитектуре

| № | Проблема                                                                                                         | Какой сценарий страдает                                  | Обоснование                                                                                                            |
|---|------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| 1 | DWH на SQL Server – низкая производительность сложных запросов (отчёты можно ждать часами)                       | Быстрая подготовка отчётности для управленческих решений | Задержки в принятии решений, потеря конкурентного преимущества (например, несвоевременное выявление финансовых рисков) |
| 2 | Бизнес-логика внутри DWH (хранимые процедуры, ETL) – каждое изменение требует перестройки хранилища              | Независимое развитие финтеха и ИИ-направлений            | Новые финансовые продукты или ИИ-модели требуют недель на интеграцию из-за работ с DWH                                 |
| 3 | ESB на Apache Camel – синхронная "точка-точка", плохо масштабируется и не поддерживает события реального времени | Масштабирование для новых бизнесов                       | Подключение фарм-компании потребует переписывания маршрутов и нагрузки на монолитную шину                              |
| 4 | Монолитность данных – медицинские карты, финансы, инвентаризация находятся в одной БД                            | Безопасность медицинских данных                          | Риск утечки медтайны через аналитические отчёты, сложно разграничить доступ аналитиков                                 |
| 5 | PowerBuilder – это устаревший интерфейс операторов                                                               | Операционная эффективность клиник                        | Сложно модернизировать рабочие места, медленный вывод новых функций (запись к врачу)                                   |
| 6 | Отсутствие Data Catalog                                                                                          | Быстрая подготовка отчётности                            | Неизвестно, какие данные есть; аналитики тратят дни на поиск и согласование, дублируют отчёты                          |
|   |                                                                                                                  |                                                          |                                                                                                                        |

3. Приоритизация проблем
Матрица Эйзенхауэра

|                                     | Срочно                                                                                                                                                                                         | Не срочно                                                                           |
|-------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| Важно (критично для выручки/рисков) | 1. Низкая производительность DWH – тормозит управленческие решения, влияет на финансовое планирование банка 2. ESB – узкое место – при подключении фармы станет критично                                                                                                                                   | 5. PowerBuilder – не влияет на выручку напрямую, можно заменить в последнюю очередь |
|                                     |                                                                                                                                                                                                |                                                                                     |

MoSCoW для целевой архитектуры


| Категория   | Элементы                                                                                                                                                                                               |
|-------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Must have   | Портал самообслуживания с разграничением доступа (без медкарт); Доменная модель и Kafka для событий; Миграция клинического домена в облачный Lakehouse; Отказ от бизнес-логики в DWH – вынос в сервисы |
| Should have | Data Catalog для доменов; Изоляция домена "Медицинские данные"; Интеграция с фармой через Kafka                                                                                                        |
| Could have  | Полное отключение SQL Server 2008; Замена PowerBuilder на веб-интерфейс                                                                                                                                |
| Won't have  | Переезд домена медицинских карт в облако; аналитика в режиме реального времени для всех доменов                                                                                                        |
|             |                                                                                                                                                                                                        |


С точки зрения бизнеса:
- Выручка: медленные отчёты мешают быстро оценить финансовые риски (кредитный портфель) и эффективность клиник;
- Скорость выхода на рынок: независимость доменов является ключевой целью;
- Качество сервисов: безопасность медицинских данных имеют высокую важность, но не срочна, так как прямого нарушения нет;
- Операционная эффективность: PowerBuilder мешает, но не критично для отчётности или новых направлений. Можно отложить
